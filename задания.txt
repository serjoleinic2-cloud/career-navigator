TITLE: CAREER NAVIGATOR — ARCHITECTURE FIX (EVENT LAYER CLEANUP)

GOAL:
Fix architecture violation where UI layer directly calls core logic.
Convert system to event-driven interaction model.

CURRENT ISSUE:
MissionScreen directly imports and calls:
- applyMissionResult from skill_engine

This breaks architecture rule:
UI must NOT directly call core logic functions.

FINAL ARCHITECTURE RULE:

MissionScreen (UI)
    → emits EVENT
skill_engine (CORE)
    → processes event
world_renderer (VIEW)
    → only renders state

--------------------------------------

TASK 1 — MissionScreen FIX

FILE:
src/screens/MissionScreen/MissionScreen.tsx

REMOVE:
- import { applyMissionResult } from '../../core/skill_engine';
- direct call to applyMissionResult()

REPLACE WITH:

Use event system:

import { emit } from '../../core/events/system_event_bus';

Replace handleSubmit logic:

emit('MISSION_SUBMIT', {
  text: textInput,
  checked: Array.from(checkedItems),
  score: reflectionScore,
});

DO NOT process result in UI.
DO NOT compute success/failure in UI.

UI only emits event.

--------------------------------------

TASK 2 — skill_engine EVENT HANDLER

FILE:
src/core/skill_engine.ts

ADD event listener:

on('MISSION_SUBMIT', (payload) => {
  submitTask(payload);
});

OR if event system requires registration:
ensure skill_engine subscribes to system_event_bus.

MOVE ALL LOGIC INTO skill_engine:
- scoring
- progression updates
- node state updates

UI must not know results logic.

--------------------------------------

TASK 3 — REMOVE DIRECT COUPLING

Ensure:
- MissionScreen does NOT import skill_engine functions
- ONLY event bus is used

--------------------------------------

TASK 4 — VERIFY DATA FLOW

Must be ONLY:

MissionScreen
   → emit('MISSION_SUBMIT')
skill_engine
   → updates state
world_renderer
   → re-renders from state

--------------------------------------

PROHIBITED:
- no direct function calls from UI to core
- no applyMissionResult in UI
- no duplicated scoring logic in UI

--------------------------------------

EXPECTED RESULT:

- Clean event-driven architecture
- UI fully decoupled from core engine
- skill_engine becomes single authority
- system ready for modular professions (DLC system)

--------------------------------------

IMPORTANT:
Do NOT refactor UI design.
Do NOT change styling.
Only fix architecture coupling.

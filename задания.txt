Ок, это уже нормальный шаг — ты наконец добавляешь knowledge layer, а не ещё один runtime/engine.

Но тут важно сразу зафиксировать структуру, иначе Playbook начнёт дублировать SkillNode advice (и снова разъедется архитектура).

📘 Как правильно структурировать Playbook (без дублирования)
🧠 Базовый принцип

У тебя теперь 3 уровня знаний:

1. SkillNode advice      → "что делать сейчас" (операционный уровень)
2. TaskContent           → "как выполнить задачу" (пошагово)
3. PlaybookEntry         → "почему и как это работает глубоко" (теория + шаблоны + стратегия)
✅ КЛЮЧЕВОЕ ПРАВИЛО

Playbook НЕ должен отвечать на:

"что мне делать сейчас"

Playbook отвечает на:

"как это устроено в индустрии"
"какие есть паттерны"
"какие шаблоны используют реальные кандидаты"
"как думают интервьюеры / рекрутеры"
🧩 1. STRUCTURE (как сделать правильно)
📦 PlaybookEntry (канонический формат)
export type PlaybookEntry = {
  id: string;
  title: string;
  category: 'resume' | 'linkedin' | 'interview' | 'salary' | 'networking';

  content: string; // deep explanation (1–3 pages equivalent)

  templates: string[]; // reusable structures (NOT advice)
  examples: string[];   // real-world examples
  checklist: string[];  // self-check system

  tags: string[]; // optional but IMPORTANT for filtering
};
🧱 2. КАК ИЗБЕЖАТЬ ДУБЛИРОВАНИЯ
❌ НЕ ДЕЛАТЬ

Playbook НЕ должен содержать:

"Write your resume summary like this…" → ❌ (это TaskContent)
"Improve your LinkedIn headline…" → ❌ (это SkillNode advice)
✅ ДЕЛАТЬ

Playbook должен содержать:

🔹 Resume Summary Formula

формулы типа:

[Role] with [X years] experience in [stack]...
🔹 STAR breakdown system
S/T/A/R explanation
what recruiters look for in each part
🔹 Salary negotiation psychology
anchoring effects
BATNA logic
why recruiters ask ranges

🔗 5. КАК СВЯЗАТЬ С TASKS (ВАЖНО)

В Task UI:

→ fetch(playbookReference)
🧭 6. CATEGORY MAPPING (чтобы не превратилось в мусор)
Category	Use case
resume	structure, bullets, ATS
linkedin	headline, profile, SEO
interview	STAR, behavioral, technical
salary	negotiation, offers
networking	referrals, messages
🧠 7. КРИТИЧЕСКАЯ АРХИТЕКТУРНАЯ ЗАЩИТА
🚫 Запрещено:
Playbook → не вызывает runtime
Playbook → не знает о SkillNode state
Playbook → не содержит "steps of journey"
Playbook → не содержит UI logic
✅ Разрешено:
TaskContent → ссылается на Playbook
Playbook → полностью статический
Playbook → offline-only (TS constants)

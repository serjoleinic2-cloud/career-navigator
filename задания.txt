Это хороший модуль, но я бы не делал один Share System. Я бы сразу разделил его на две независимые подсистемы:

Export (получение данных)
Share (передача пользователю)

Это разные ответственности.

Правильная архитектура
Runtime
      │
      ▼
Share Mapper
      │
      ▼
Share Model
      │
 ┌────┴────────────┐
 │                 │
 ▼                 ▼
Export System   Share System
(JSON/CSV/PDF)  (PNG/Text/Web Share)

Таким образом Runtime вообще не знает, что существует шаринг.

1. ShareModel

Сначала создаётся единая модель.

export interface ShareModel {

    profession: string;

    completedSkills: number;

    totalSkills: number;

    readinessScore: number;

    confidenceScore: number;

    currentChapter: string;

    quote: string;

    themeColor: string;

}

UI, PNG, PDF, JSON используют одну модель.

2. Share Mapper

Создать

share_mapper.ts

RuntimeState

Что дать Opencode

Я бы дал именно такое техническое задание:

Реализовать Share/Export System с разделением ответственности.

Требования:

1. Не изменять Runtime.

2. Создать папку:

src/core/share/

    share_mapper.ts
    share_service.ts
    share_image.ts
    native_share.ts

3. Создать папку:

src/core/export/

    export_service.ts
    export_json.ts
    export_csv.ts

4. Создать ShareModel:

profession
completedSkills
totalSkills
readinessScore
confidenceScore
currentChapter
quote
themeColor

5. Создать share_mapper.ts:

JourneyRuntimeState + UIState
↓

ShareModel

6. Share Card должна использовать только ShareModel.

7. ShareService:

copyText()

copyImage()

shareText()

shareImage()

nativeShare()

8. ExportService:

exportJSON()

exportCSV()

Подготовить архитектуру для exportPDF() без реализации.

9. Все экспорты должны работать полностью offline через Blob/File.

10. Не выполнять никаких сетевых запросов.

11. Добавить ShareOptions:

hideScores
hideProfession
hideProgress
hideQuote

12. Runtime, Event Bus, Learning Engine и Persistence не изменять.

13. Архитектура должна позволять легко добавить PDF, Markdown и другие форматы экспорта без изменения существующего API.

Это решение соответствует уже выбранной вами архитектуре: Runtime остаётся источником данных, Mapper преобразует их в модель представления, а Export и Share становятся независимыми сервисами, которые легко расширять новыми форматами и способами обмена без затрагивания ядра приложения.
